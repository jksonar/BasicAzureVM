# Basic Azure VM (Terraform)

A minimal, learning-focused Terraform project that provisions a single Linux VM
on Azure with its own networking stack. This is Architecture 1 (⭐) from the
broader Azure + Terraform practice series — see [plan.txt](plan.txt).

## Architecture

```
                    Internet
                       |
                 Public IP
                       |
                 +-----------+
                 |   Azure   |
                 |    VM     |
                 |  Ubuntu   |
                 +-----------+
                       |
                    VNet
                       |
                 +-----------+
                 |   NSG     |
                 +-----------+
```

## What gets created

| Resource | Terraform type |
|---|---|
| Resource Group | `azurerm_resource_group` |
| Virtual Network | `azurerm_virtual_network` |
| Subnet | `azurerm_subnet` |
| Network Security Group + rules | `azurerm_network_security_group`, `azurerm_network_security_rule` |
| NSG ↔ Subnet association | `azurerm_subnet_network_security_group_association` |
| Public IP (Standard, Static) | `azurerm_public_ip` |
| Network Interface | `azurerm_network_interface` |
| Linux VM (Ubuntu 22.04 LTS) | `azurerm_linux_virtual_machine` |
| SSH keypair (auto-generated) | `tls_private_key`, `local_sensitive_file`, `local_file` |
| Azure auth context | `data.azurerm_client_config` |

SSH password authentication is disabled — the VM is provisioned with a
key-pair generated by Terraform itself, so no key needs to exist beforehand.

## Project layout

```
.
├── providers.tf              # required providers (azurerm, tls, local)
├── variables.tf              # all input variables
├── locals.tf                 # name prefix + merged tags
├── main.tf                   # all resources
├── outputs.tf                # exported values (IPs, SSH commands, etc.)
├── terraform.tfvars.example  # sample variable values — copy to terraform.tfvars
└── .gitignore                # excludes state, tfvars, generated ssh/ keys
```

## Prerequisites

- [Terraform](https://developer.hashicorp.com/terraform/install) >= 1.5.0
- [Azure CLI](https://learn.microsoft.com/cli/azure/install-azure-cli) (used to authenticate)
- An Azure subscription you're allowed to deploy into

## Setup

1. **Authenticate to Azure**

   ```bash
   az login
   az account set --subscription "<subscription-id-or-name>"
   ```

2. **Copy and edit the variables file**

   ```bash
   cp terraform.tfvars.example terraform.tfvars
   ```

   At minimum, restrict SSH access to your own IP instead of the wide-open
   default. Find your IP with:

   ```bash
   curl -s ifconfig.me
   ```

   Then set it in `terraform.tfvars`:

   ```hcl
   nsg_rules = {
     AllowSSH = {
       priority                   = 100
       direction                  = "Inbound"
       access                     = "Allow"
       protocol                   = "Tcp"
       source_port_range          = "*"
       destination_port_range     = "22"
       source_address_prefix      = "YOUR.IP.ADDRESS.HERE/32"
       destination_address_prefix = "*"
     }
   }
   ```

3. **Initialize Terraform**

   ```bash
   terraform init
   ```

4. **Review the plan**

   ```bash
   terraform plan
   ```

5. **Apply**

   ```bash
   terraform apply
   ```

## Connecting to the VM

Terraform generates an SSH keypair on apply and writes the private key to
`./ssh/<prefix>-<environment>_id_rsa` (permissions `0600`, gitignored).

After `apply` finishes, print a ready-to-use SSH command:

```bash
terraform output -json ssh_connection_commands
```

Or connect manually:

```bash
ssh -i ./ssh/basicvm-dev_id_rsa azureuser@$(terraform output -raw public_ip_addresses)
```

## Inputs

| Name | Description | Type | Default |
|---|---|---|---|
| `prefix` | Short name prefixed to all resource names | `string` | `"basicvm"` |
| `environment` | Environment name, used in naming/tags | `string` | `"dev"` |
| `location` | Azure region | `string` | `"eastus"` |
| `vnet_address_space` | VNet CIDR(s) | `list(string)` | `["10.0.0.0/16"]` |
| `subnet_address_prefixes` | Subnet CIDR(s) | `list(string)` | `["10.0.1.0/24"]` |
| `admin_username` | Linux admin username | `string` | `"azureuser"` |
| `vm_size` | VM SKU size | `string` | `"Standard_B1s"` |
| `vm_count` | Number of VMs (and matching NICs/public IPs) | `number` | `1` |
| `nsg_rules` | Map of NSG rules created via `for_each` | `map(object)` | one `AllowSSH` rule open to `*` — restrict before use |
| `tags` | Extra tags merged into every resource | `map(string)` | `{}` |

## Outputs

| Name | Description |
|---|---|
| `resource_group_name` | Name of the created resource group |
| `vnet_id` | VNet resource ID |
| `subnet_id` | Subnet resource ID |
| `network_security_group_id` | NSG resource ID |
| `vm_names` | Names of the created VM(s) |
| `public_ip_addresses` | Public IP(s) of the VM(s) |
| `private_ip_addresses` | Private IP(s) of the VM(s) |
| `ssh_private_key_path` | Path to the generated private key (sensitive) |
| `ssh_connection_commands` | Ready-to-run `ssh` commands for each VM |
| `current_subscription_id` | Azure subscription ID in use |

## Scaling to more than one VM

Bump `vm_count` in `terraform.tfvars` — matching public IPs, NICs, and VMs
are created automatically (driven by `count` in [main.tf](main.tf)).

## Cleaning up

Destroy all resources created by this project:

```bash
terraform destroy
```

This also removes the resource group and everything inside it. The
generated SSH keys under `./ssh/` are local files and are **not** removed
by `terraform destroy`; delete them manually if you no longer need them.

## Security notes

- The default `AllowSSH` rule in `terraform.tfvars.example` uses a
  placeholder — always scope it to your own IP/CIDR (`/32`) rather than `*`.
- Password authentication is disabled on the VM; SSH key auth only.
- State files, `terraform.tfvars`, and the generated `ssh/` directory are
  excluded via `.gitignore` — never commit them, since they contain
  sensitive values (private key, resource details).

## Terraform concepts demonstrated

- Variables (`variables.tf`) with typed defaults, including a nested
  `map(object({...}))`
- Locals (`locals.tf`) for naming and tag merging
- Outputs (`outputs.tf`), including a computed list via a `for` expression
- `for_each` over `var.nsg_rules` to create NSG rules
- `count` over `var.vm_count` to scale public IPs/NICs/VMs together
- A data source (`data.azurerm_client_config.current`)
- Resource dependencies via implicit references (e.g. NIC → subnet → VNet)
